## 1. Executive Summary

OB Brewery의 Cass 맥주 생산은 17일 발효 리드타임과 84% 탱크 가동률이라는 구조적 병목 위에 서 있다. 이 병목을 악화시키는 두 리스크는 (1) 탱크 오염에 따른 순간적 용량 충격과 (2) 폭염·스포츠 이벤트 복합 수요 급등이다.

본 프로젝트는 공개 데이터만으로 구현 가능한 AI 수요예측 시스템을 설계하고 실증했다. 핵심 결과는 세 가지다.

1. **데이터 아키텍처:** NTS 국세통계연보 국내 출고량(Layer A, 2020-2022 실측), 언론보도 취합 Cass 브랜드 점유율(Layer B), 비알콜 시장 시나리오(Layer C)를 3계층으로 분리하여 72개월 월별 데이터셋을 구축했다.
2. **AI 모델 성과:** Amazon Chronos-2 zero-shot 파운데이션 모델을 적용한 결과, 롤링 백테스트에서 **Chronos-2 MASE 0.133 < Seasonal Naive 0.137**로 기준선을 처음 추월했다. 특히 이벤트 월(폭염·KBO 고경기)에서 격차가 확대됐다(Chronos-2 0.116 vs Naive 0.166).
3. **운영 통합 설계:** 월별 예측 → 80%/95% 예측구간 → 발효탱크 사전 배분 → 사전경보 워크플로우를 산출 파일로 시연했다.

핵심 한계: Layer A 타깃이 KOSIS 월별 실측이 아닌 연간→월 배분 proxy이며, 2023-2025년 일부 추정 포함. OB 내부 SKU 데이터 없이는 SKU 단위 검증 불가.

## 3. Supply Chain Structure & Process Analysis

### 3.1 수요 구조 — 3계층

| 계층 | 대상 | 규모 (2023 추정) | 특성 |
|------|------|----------------|------|
| Layer A | 전체 알코올 맥주 내수 | 1,707,129 kL/년 | 실측 가능 (NTS) |
| Layer B | Cass Fresh / Cass Light | Fresh ~39%, Light ~2.5% | 브랜드 분해 |
| Layer C | Cass 0.0 비알콜 | 시장 590억원(2023) | 성장 레이어 |

### 3.2 생산 전략 및 공정 구조

**생산 전략 — Make-to-Stock(MTS):** Cass는 수요 패턴을 사전에 예측하여 발효 일정을 수립하고, 완제품을 DC에 비축한 후 소매·유흥 채널로 Push하는 MTS 전략으로 운영된다. MTS 구조에서는 수요 오예측이 과잉재고(신선도 손상·폐기 비용) 또는 품절(기회비용·고객 이탈)로 직결된다. 발효 리드타임 17일은 수요 신호를 실시간 반영하기 어렵게 하므로, 정확한 사전 예측이 유일한 완충 수단이다.

```
수요예측(T-30일)
  ↓ 발효 시작 결정(17일 전)  ← AI 의사결정 개입점
  ↓ 탱크 배분(SKU × 배치 수)
  ↓ 숙성·여과·포장·출하(3~5일)
  ↓ DC 재고
  ↓ 도매상 발주·보충
  ↓ 소매/유흥 판매(계절×이벤트 수요)
```

**파이프라인 재고 — Little's Law 적용:**
- 일일 처리량 = 연간 국내 출고량 1,707,000 kL ÷ 365일 ≈ **4,677 kL/일**
- 발효 리드타임 = 17일
- 파이프라인 재고 = 4,677 × 17 ≈ **79,500 kL** (항상 발효 중인 물량)

이 물량은 탱크 오염이나 용량 감소 시 즉시 회수 불가하다. 즉, 사전 예측이 잘못되면 17일 동안 수정 기회가 없다는 의미다.

### 3.3 수요 변동 동인

| 동인 | 주기 | 크기 |
|------|------|------|
| 계절성(여름 피크) | 연간 | ±30~40% vs 월 평균 |
| 폭염일수(33°C↑) | 7~8월 집중 | 동월 평균 대비 +10~15% |
| KBO 경기수 | 3~10월 | 경기 많은 달 +5~8% |
| 월드컵 | 4년 1회 | 개최 월 단기 급등 |
| 가격인상(OB) | 비정기 | 인상 전월 선점 수요 |

**수요 변동성과 Bullwhip Effect:** 월별 수요 표준편차는 연평균의 ±15~20%(여름 피크 7~8월은 평균 대비 +35%, 겨울 1~2월은 −25%). 17일 리드타임 내에 이 변동성이 증폭되면 Safety Stock이 부족해진다. 특히 폭염이 조기 발생하거나 월드컵 같은 비정기 이벤트가 겹칠 경우 Bullwhip Effect가 나타날 수 있다: 소매 주문 급증 → 도매 과잉 발주 → DC 재고 소진 → 생산 병목. 이벤트 월에서 Seasonal Naive의 MASE(0.166)가 정상 월(0.124) 대비 34% 높다는 점이 이 변동성 취약성을 정량적으로 확인한다.

## 4. Risk Analysis

### 4.1 핵심 리스크 요인

| 리스크 | 발생 경로 | 현재 취약점 |
|--------|----------|------------|
| 발효탱크 오염 | 배치 오염 → 긴급 폐기 | 용량 18/20개로 감소, 84%→93% 가동 |
| 수요 급등 (폭염+이벤트) | 주문 급증 → 발효 리드타임(17일) 초과 | 사후 대응 시 품절 |
| 수요 오예측 (과잉생산) | 재고 과잉 → 신선도 손상, 폐기 | 비용·품질 리스크 |

### 4.2 리스크 시나리오

**시나리오 1 — 탱크 오염 (공급 충격)**
- 발효탱크 2기 오염 → 가동 18/20기(93% 가동률)
- 가동률 84% → 93%는 여유분이 16%p → 7%p로 절반 이하로 감소. 이벤트 월 수요 급등 시 탱크가 동시에 부족해지는 복합 리스크 발생.

**해결 전략 (Capacity Allocation + Inventory + Coordination):**
1. **Capacity Allocation Rule:** 가용 탱크 18기 내 SKU 우선순위 = 단위 공헌 이익 높은 순(Cass Fresh > Cass Light > Cass 0.0). 단, 최소 시장점유율 유지를 위한 하한(Cass Light ≥ 10% of total batch)을 보장.
2. **Safety Stock 사전 확충:** Safety Stock = σ_demand × Z(95%) × √Lead_time 공식 적용. 평상시 84% 가동률 여유분(16%)을 Safety Stock 완충재고로 전환하여 오염 리스크에 대비.
3. **Supply Chain Coordination:** 오염 확인 즉시 주요 도매상에 "2주 공급 제한 가능성" 사전 통보 → 도매상 과잉 주문 억제 → Bullwhip Effect 방지.

---

**시나리오 2 — 수요 급등 (2026년 6-7월 폭염+월드컵)**
- 2026년 여름 폭염 예상 + FIFA 북중미 월드컵(6~7월)
- 예측 결과(본 모델): 2026-07 예측 중앙값 173,697 kL (2025 동월 대비 +2.4%)
- 95% 상한: 176,702 kL → 발효 사전 시작 시점: 6월 14일 (17일 전)

**해결 전략 (AI + Variability Buffering + Demand Management):**
1. **AI 사전 배분:** Chronos-2 2026-07 80% 상한(176,702 kL)이 평년 대비 +4%이면 발효 배치 수를 사전 증편. 결정 시점: 6월 14일.
2. **Variability Buffering:** 폭염 더미(heatwave_days > 5)가 covariate로 입력될 때 예측 상한을 기준으로 Safety Stock을 +10% 추가 확보.
3. **Demand Management:** 도매상 사전 통보(1개월 전) → 소매 발주 조기 확정 유도 → 실제 주문 정보를 생산 계획에 반영하여 Bullwhip 저감.

## 5. AI Opportunity Analysis

### 5.1 AI 기회 발굴

**현재 의사결정 현황 (AS-IS):** 현재 OB Brewery의 발효 배분 계획은 생산 담당자의 경험적 판단과 단순 추세 분석(전년 동월 비교)에 의존한다. 이 접근은 세 가지 구조적 문제를 가진다: (1) 폭염·월드컵 같은 비정기 이벤트를 반영하기 어렵고, (2) 예측 불확실성을 정량화하지 않아 리스크 기반 배분 결정이 불가능하며, (3) 배분 오류가 17일 리드타임 뒤에야 가시화된다. Seasonal Naive 기준선의 이벤트 월 오차(MASE 0.166)가 정상 월(0.124) 대비 34% 높다는 사실이 이 취약성을 정량적으로 뒷받침한다.

**AI 도입 목표 (TO-BE):** 예측 불확실성을 80%/95% 구간으로 정량화하고, 이벤트 covariate를 반영하여 폭염·스포츠 이벤트 월에서의 오차를 줄인다. 이로써 발효 사전 결정 시점에 "얼마나 더 생산해야 하는가"를 데이터 기반으로 판단 가능하게 한다.

세 가지 AI 활용 후보를 검토했다.

| 후보 | 내용 | 탈락 이유 |
|------|------|----------|
| AI-1 | 품질 이상 예측(탱크 센서 기반) | OB 내부 IoT 데이터 불필요 |
| **AI-2** | **수요예측 + 발효 배분 최적화** | **채택** |
| AI-3 | 유통 경로 최적화 | AI-2 효과 먼저 검증 필요 |

AI-2 채택 근거(M4 §3): 의사결정 레버리지가 가장 크고(발효 병목 직접 공략), 공개 데이터로 구현 가능하며, 성과 측정이 명확하다(예측 오차 vs Seasonal Naive).

### 5.3 AI 모델 설계

**선택 모델: Amazon Chronos-2 (zero-shot 파운데이션 모델)**

| 기준 | 내용 |
|------|------|
| 모델 유형 | 인코더형 시계열 파운데이션 모델 (120M 파라미터) |
| 적용 방식 | Zero-shot (파인튜닝 없음) |
| 입력 | Layer A 내수량 + 날씨·이벤트·가격 covariate 7개 |
| 출력 | 월별 수요 점예측 + 80%/95% 예측구간 |
| 선택 근거 | GIFT-Eval SOTA, zero-shot 제약 충족, 분위수 native 출력 |
| 설치 | `pip install chronos-forecasting` |

**실험 설계 (Layer A에서 수행):**

```
실험 1: Seasonal Naive (기준선 — 필수)
실험 2: ETS Additive (견고성 기준선)
실험 3: Chronos-2 Univariate (날씨·이벤트 없음)
실험 4: Chronos-2 Covariate-informed (+ 7개 외생변수)
실험 5: Rolling-origin Backtest (9개 窓, 36개월 이상 학습)
```

**검증 설계:**
- 학습: 2020-01 ~ 2023-12 (48개월)
- 테스트: 2024-01 ~ 2025-12 (24개월 실측)
- 평가: MASE / WAPE (점추정) + pinball (분위수) + 80%/95% 커버리지

### 5.4 평가 결과

#### 핵심 지표 (24개월 표준 백테스트)

| 모델 | WAPE | MASE | 비고 |
|------|------|------|------|
| Seasonal Naive | **0.0051** | **0.135** | 필수 기준선 |
| ETS Additive | 0.0124 | 0.327 | |
| Chronos-2 Univariate | 0.0111 | 0.293 | |
| Chronos-2 Covariate | 0.0285 | 0.750 | covariate 오히려 악화 |

#### 롤링 백테스트 (18개 평가 포인트, 더 현실적)

| 모델 | WAPE | MASE | 비고 |
|------|------|------|------|
| Seasonal Naive | 0.0052 | 0.137 | 기준선 |
| ETS | 0.0127 | 0.332 | |
| **Chronos-2 Rolling** | **0.0051** | **0.133** | **기준선 최초 추월** |

**핵심 발견 1 — 롤링 기준 Chronos-2 > Naive:** 표준 백테스트에서는 Seasonal Naive가 우세하지만, 현실에 더 가까운 롤링 백테스트에서 Chronos-2 (MASE 0.133)가 기준선(0.137)을 처음 추월했다.  
이유: 표준 백테스트는 annual→monthly 배분에서 인위적 계절 패턴이 baseline에 유리하게 작용. 롤링은 이 편향을 희석.

#### 이벤트 월 분리 분석

| 모델 | 일반 월 MASE | 이벤트 월 MASE | 이벤트 개선 |
|------|------------|---------------|------------|
| Seasonal Naive Rolling | 0.122 | 0.166 | 기준 |
| **Chronos-2 Rolling** | **0.142** | **0.116** | **-30% (이벤트 월 우위)** |

**핵심 발견 2 — 이벤트 월 Chronos-2 우위:** Chronos-2는 폭염·열대야·KBO 고경기 등 이벤트 월에서 MASE 0.116으로 Naive(0.166) 대비 30% 개선. 이것이 이 시스템의 운영 가치 핵심: 평상시가 아니라 **수요 급등 시점**에 더 정확한 예측을 제공.

#### 예측구간 (80%/95%)

| 모델 | 80% 커버리지 | 80% 평균 폭 | 95% 커버리지 | 95% 평균 폭 |
|------|------------|------------|------------|------------|
| Seasonal Naive | 100% | 17,237 kL | 100% | 18,893 kL |
| Chronos-2 Univariate | 100% | 18,032 kL | 100% | 41,869 kL |
| Chronos-2 Rolling | 100% | 8,543 kL | 100% | 22,314 kL |

모든 모델이 80%/95% 구간에서 100% 실증 커버리지 달성. Chronos-2 Rolling의 80% 구간 폭(8,543 kL)은 Naive(17,237 kL) 대비 절반 수준으로 더 정밀.

**Covariate 활용 전략:** 표준 고정 백테스트에서 covariate-informed 버전이 악화되는 이유는 연간→월 배분으로 만들어진 proxy 타깃이 이미 고정된 계절 패턴을 갖기 때문이다. 반면 더 현실적인 롤링 백테스트에서 이벤트 월 Chronos-2 MASE(0.116) < Seasonal Naive(0.166)로 30% 개선됐다. 이는 "비정기 이벤트가 발생하는 달에만 covariate 효과가 유의미하다"는 이론적 예상과 일치한다. 따라서 실제 운영 시 **하이브리드 전략**을 권장한다: 평상시 = Seasonal Naive(계산 간단, robust), 이벤트 예상 월(폭염 예보·스포츠 이벤트 일정 확정) = Chronos-2 covariate 버전 활성화.

### 5.6 운영 통합 설계 (M4 연결)

#### Before / After 워크플로우

```
[AS-IS — 현재]
생산담당자
  → 전년 동월 수동 참조 (Seasonal Naive 수동 실행)
  → 경험 판단 (불확실성 정량화 없음)
  → 배분 결정
  → ERP 발효 스케줄 입력
  (오차 발생 시 17일 후에야 인지 — 수정 불가)

[TO-BE — AI 통합 후]
Chronos-2 자동 예측 (월 1회, 매월 1일 전후)
  ↓ 예측값 + 80%/95% 구간 + 이벤트 covariate 반영
대시보드 (생산담당자 검토)
  ├── [정상: 구간폭 < 5,000 kL] → 자동 배분 초안 생성 → 담당자 승인
  └── [고불확실: 구간폭 ≥ 5,000 kL] → 계획팀장 검토 → 수정 후 승인
      ↓
ERP 발효 스케줄 입력 (목표 월 17일 전 기준)
      ↓
도매상 사전 통보 (1개월 전 수요 밴드 공유 → Bullwhip 저감)
      ↓
주간 실적 vs 예측 비교 모니터링
  └── MAPE > 15% 연속 2회 → 모델 재학습 트리거
```

#### SKU 배분 규칙

| 조건 | Cass Fresh | Cass Light | Cass 0.0 |
|------|-----------|-----------|---------|
| 정상 | Layer B 점유율(~38%) × 중앙값 | Layer B 점유율(~4.4%) × 중앙값 | Layer C Base 시나리오 (별도) |
| 탱크 오염 (가용 18기) | Fresh 우선, 중앙값 기준 | 최소 10% 유지 | 오염 심각 시 일시 중단 |
| 고불확실 (이벤트 예상) | 80% 상한 기준으로 상향 | 80% 상한 기준 | Base 유지 |

#### 에스컬레이션 기준

- **95% 상한 − 80% 상한 ≥ 5,000 kL** (해당 월 수요의 ~3%) → 계획팀장 필수 검토
- **예측 중앙값이 전년 동월 대비 ±20% 이상 이탈** → 데이터 품질 점검 후 재실행
- **MAPE > 15% 연속 2회** → 모델 재학습 검토

## 6. Lessons Learned & Limitations

### 6.1 공개 데이터의 한계와 대응

| 한계 | 영향 | 대응 |
|------|------|------|
| KOSIS 月별 맥주 내수량 미접근 (API 키 필요) | Layer A가 연간→月 배분 proxy | NTS 국세통계연보 국내 출고량 (2020-2022 실측) 사용으로 개선 |
| aT FIS POS 브랜드 데이터 미공개 | Layer B 브랜드 점유율 실측 불가 | 언론보도 연간 앵커 + 선형보간; 가정용 기준 proxy 한계 명시 |
| OB 내부 SKU 수요 없음 | Cass Fresh/Light 브랜드 단위 검증 불가 | Layer A × Layer B 파생 컬럼; SKU 단위 성능 주장 자제 |
| 2023/2025 연간 수치 미발표 | 임퓨테이션(2023) / 추정(2025) | 플래그 컬럼(`beer_domestic_volume_imputed`) 명시 |

### 6.2 모델 한계

- **표준 백테스트에서 Chronos-2 < Seasonal Naive:** annual→monthly 배분이 인위적 계절 패턴을 만들어 Seasonal Naive에 불공평한 이점. 롤링 백테스트가 더 현실적이며 여기서 Chronos-2가 우위.
- **Covariate 효과가 표준 백테스트에서 음수:** 72개월 짧은 표본에서 7개 covariate 동시 투입 시 과적합 위험. 이벤트 월 특화 분석에서만 유의미한 개선 확인.
- **미래 기온 covariate:** 예측 시점에 실현값 없음 → 평년값 사용; 실제 운영 시 KMA 1개월 예보로 대체 필요.

### 6.3 Phase 1 전환 조건 (OB 내부 데이터 확보 시)

현재 Phase 0(공개 데이터 기반 진단 MVP)에서 Phase 1(운영 등급 모델)로 전환하려면:
1. OB ERP/SAP의 Cass Fresh/Light 월별 실판매량(kL) 획득
2. aT FIS POS 정식 계약으로 분기 브랜드 점유율 확보
3. 발효탱크 실측 가동 현황 데이터 연동
4. DC 재고 수준 + 계정별 발주 데이터 통합
