## 2. 모델 구축

### 2.1 선택 모델

| 항목 | 내용 |
|------|------|
| **모델** | Amazon **Chronos-2** (zero-shot 시계열 파운데이션 모델) |
| **파라미터** | 120M (encoder 기반) |
| **적용 방식** | Zero-shot (파인튜닝 없음 — 프로젝트 규정 충족) |
| **출력** | 점예측 + 분위수(Q10/Q50/Q90) → 80%/95% 예측구간 |
| **선택 근거** | GIFT-Eval·fev-bench SOTA / covariate 입력 가능 / 분위수 native 출력 |
| **설치** | `pip install chronos-forecasting` |
| **모델 캐시** | `.hf_cache/` (워크스페이스 로컬) |

### 2.2 실험 설계

| 실험 번호 | 모델 | 입력 | 목적 |
|----------|------|------|------|
| 1 | **Seasonal Naive** | Layer A 내수량 | 필수 기준선 (전년 동월) |
| 2 | **ETS Additive** | Layer A 내수량 | 견고성 기준선 |
| 3 | **Chronos-2 Univariate** | Layer A 내수량 | AI zero-shot 기본 성능 |
| 4 | **Chronos-2 Covariate** | Layer A + covariate 7개 | AI + 외생변수 효과 |
| 5 | **Rolling-origin Backtest** | 위 모델 전체 | 현실적 성능 평가 |

### 2.3 검증 설계

| 항목 | 값 |
|------|-----|
| 학습 컨텍스트 | 2020-01 ~ 2023-12 (48개월) |
| 테스트 기간 | 2024-01 ~ 2025-12 (24개월 실측) |
| 롤링 窓 수 | 9개 |
| 최소 학습 길이 | 36개월 |
| 롤링 지평 | 6개월 |
| 평가 지표 | MASE, WAPE + pinball@0.1/0.5/0.9 + 80%/95% empirical coverage |
| 이벤트 분리 | 정상 월 vs 이벤트 월 (폭염·열대야·KBO 고경기·가격인상) |

## 3. 결과 및 결론

### 3.1 핵심 평가 지표

#### 표준 고정 백테스트 (학습 2020-2023 / 테스트 2024-2025, 24개월)

| 모델 | WAPE | MASE | 기준선 대비 |
|------|------|------|-----------|
| **Seasonal Naive** | **0.0051** | **0.135** | 기준선 |
| ETS Additive | 0.0124 | 0.327 | −2.4× 악화 |
| Chronos-2 Univariate | 0.0111 | 0.293 | −2.2× 악화 |
| Chronos-2 Covariate | 0.0285 | 0.750 | −5.5× 악화 |

> 표준 백테스트에서 Seasonal Naive 우세. 이유: 연간→월 배분으로 만들어진 proxy 타깃이 고정된 계절 패턴을 가져 전년 동월 베이스라인에 인위적으로 유리.

#### 롤링 백테스트 (9개 窓 × 6개월 지평, 18개 평가 포인트 — 더 현실적)

| 모델 | WAPE | MASE | 기준선 대비 |
|------|------|------|-----------|
| Seasonal Naive | 0.0052 | 0.137 | 기준선 |
| ETS Additive | 0.0127 | 0.332 | 악화 |
| **Chronos-2 Rolling** | **0.0051** | **0.133** | **−2.9% 개선 (역전)** |

> 롤링에서 Chronos-2 (MASE 0.133) < Seasonal Naive (0.137): **기준선 최초 추월**.

### 3.2 이벤트 월 분리 분석 — 핵심 발견

| 모델 | 정상 월 MASE (12개) | 이벤트 월 MASE (6개) | 이벤트 월 개선율 |
|------|-----------------|-----------------|-------------|
| Seasonal Naive Rolling | 0.122 | 0.166 | 기준 |
| ETS Rolling | 0.414 | 0.168 | 악화 |
| **Chronos-2 Rolling** | 0.142 | **0.116** | **−30% (이벤트 월 우위)** |

**이벤트 월 정의**: 폭염일수 > 0, 열대야 > 0, KBO 경기 > 120경기, 가격인상 월

> **운영 가치의 핵심**: Chronos-2는 정상 월에는 Naive에 밀리지만, **수요 급등이 예상되는 이벤트 월에서 30% 더 정확**하다. 발효 리드타임 17일이 존재하는 환경에서, 이 차이가 사전 배분 결정의 품질을 결정한다.

### 3.5 모델 운영 연결 (하이브리드 전략)

```

  → Seasonal Naive 사용 (단순·robust·Chronos-2와 유사 성능)

```

### 3.7 결론

**1. 데이터 구축 성과**  
공개 데이터 한계 내에서 NTS 실측(2020-2022) + 언론 앵커 Layer B + 관세청 가격 proxy로 72개월 21컬럼 데이터셋 완성. Validation 8개 항목 중 6개 PASS/PARTIAL, 1개 FAIL(beer_value). 3계층 분리 구조(A=실측 백본, B=브랜드 앵커, C=시나리오)는 가이드라인 5.3 "실측 우선, 가정 명시" 원칙을 충족한다.

**2. 모델 성과**  
Chronos-2 zero-shot은 표준 백테스트에서 Seasonal Naive에 밀리지만, 더 현실적인 롤링 백테스트(MASE 0.133 vs 0.137)와 이벤트 월(MASE 0.116 vs 0.166, −30%)에서 기준선 역전. 운영 가치는 "평상시 정확도 개선"이 아닌 **폭염·월드컵 등 수요 급등 시점의 사전 인지**에 있다. 80%/95% 구간 모두 100% empirical coverage 달성.

**3. 운영 통합 의미**  
예측 → 80% 상한 기반 발효 배치 수 계산 → SKU 배분(Fresh/Light/0.0) → 에스컬레이션 트리거의 end-to-end 워크플로우가 설계됐다. 2026-07 시나리오에서 발효 결정일(6월 14일)과 SKU별 배분량(Fresh 67,110 kL, Light 7,771 kL)이 구체적으로 산출됐다. OB 내부 SKU 수요 데이터 확보 시 Phase 1 운영 등급으로 즉시 전환 가능하다.
